
# 大模型 Function Call功能详解
# 概述
**Function Call（函数调用）** 是大模型的核心能力之一，指大模型根据用户输入的自然语言指令，**自动识别需要调用的外部工具/函数**、**生成符合格式要求的函数入参**。其本质是打通大模型与外部系统的桥梁，弥补大模型“知识时效性差、无法执行实时计算/操作”的短板。


## 技术原理与核心流程
Function Call 的实现依赖 **“工具注册 + 模型能力 + 格式约束  + 结果解析”** 四部分，核心流程如下：

### 1、工具注册：定义函数元信息
开发者需要向大模型**注册可调用的函数列表**，并提供标准化的元信息，包括：
- `name`：函数名称。
- `description`：函数功能描述（让模型判断何时调用该函数）。
- `parameters`：函数入参的结构化定义（包括参数名、类型、是否必填、参数描述）。

**比如 OpenAI JSON格式 **：
```json
[
  {
    "name": "get_weather",
    "description": "根据城市名称获取实时天气信息",
    "parameters": {
      "type": "object",
      "properties": {
        "city": {
          "type": "string",
          "description": "城市名称，如北京、上海"
        },
        "date": {
          "type": "string",
          "description": "查询日期，格式YYYY-MM-DD，可选，默认当天"
        }
      },
      "required": ["city"]
    }
  }
]
```

给大模型工具的格式，通常会遵循 JSON Schema 结构；
目前注册插件有以下 ：
1、[MCP](https://modelcontextprotocol.io/docs/getting-started/intro)的方式注册
2、YAML格式，早期Open AI采用这种格式注册插件
[Open API 提交工具](https://openai.apifox.cn/api-123708104)  
[OpenAI插件中文版](https://openai.xiniushu.com/docs/plugins/getting-started)



### 2、模型能力&格式约束
当用户输入自然语言指令（如“北京明天的天气怎么样？”），大模型结合**用户指令 + 已注册的函数元信息**，判断是否需要调用函数：
- 若不需要调用函数（如闲聊、常识问答），直接生成自然语言回答。
- 若需要调用函数，进入**函数参数生成阶段**。

需要调用函数时大模型根据用户意图，生成**符合格式要求的函数调用指令**，核心是准确提取参数。例如针对上述问题，模型生成：
```json
{
  "name": "get_weather",
  "parameters": {
    "city": "北京",
    "date": "2025-12-08"
  }
}
```

### 3、结果解析
开发者的代码解析模型生成的函数调用指令，调用对应的外部工具/接口，获取执行结果。例如调用天气API后返回：
```json
{
  "city": "北京",
  "date": "2025-12-08",
  "temperature": "5~12℃",
  "weather": "晴转多云",
  "wind": "东北风2级"
}
```

## 关键技术要点

### 1. 格式约束与 Prompt 工程
为了让模型稳定生成结构化的函数调用指令，需要通过 Prompt 明确格式要求，常见方式包括：
- **JSON 格式强制约束**：要求模型输出严格的 JSON 字符串，避免多余文本。
- **Prompt 引导**：在 Prompt 中加入 1-2 个函数调用示例，帮助模型理解任务。

```
你可以调用以下函数来回答用户问题：
{函数元信息}

请按照以下格式输出：
1. 若需要调用函数，输出 JSON 格式：{"name": "函数名", "parameters": {"参数1": "值1", ...}}
2. 若不需要调用函数，直接输出自然语言回答。

用户问题：{用户输入}
```

### 2. 模型能力要求
并非所有大模型都支持 Function Call，需要模型具备以下能力：
- **结构化输出能力**：能够精准生成 JSON 等格式的文本，而非自由文本。
- **意图理解与参数提取能力**：能够从自然语言中识别关键信息，并映射到函数参数。


### 3.大模型的函数调用&函数的结构化输出

* 原生函数调用
    * 这种是由大量意图识别、工具调用训练 + 约束解码两个步骤组成。前者通常是大量的训练保证模型准确的理解意图，并调用工具。
    * 由于概率的存在，模型不可能保证 100% 的完整 json 。
    * 那么原生函数调用能 100 % 输出 json 靠约束解码算法的功劳 ，这个算法会在 LLM每次 token 产生候选词的时
      候，对那些不符合 json格式的候选者设置负无限大的概率，从而强制模型跳过那些不合法的 json token。
-------------------------
* 基于提示词的函数调用 比如更加精心设计的**Prompt 模板**：
    * 提示工程不依赖于模型任何内置的功能。
    * 需要通过精心设计的提示词来引导任何具备强大指令遵循能力的LLM完成工具调用任务。
    * 即使基于自定义提示词，模型内部仍然拥有这些工具选择的理解能力，只是基于纯提示词无法精准保证 100% 的 json工具返回，通常需要一定的应用容错、重试层算法保证工具调用质量。
    * 应用程序的后端接收到这个包含JSON的字符串后，需要进行解析和处理，总结成提取和解析。

-------------------------
#### 3.1 原生函数调用的约束解码
一种结构化解码器（Structured Decoder）, 结构化解码器是基于文法约束的解码：在生成每个 token 时，只允许模型从“合法候选 token”中选择，这些候选是由当前上下文 + 目标 Schema 组成.

技术原理：
1、将 JSON Schema 编译成一个 有限状态机（Finite State Machine, FSM） 或 上下文无关文法（CFG）
2、每生成一个 token，就更新 FSM 状态
3、只保留能使 FSM 转移到合法状态的 token （在 logits 层屏蔽非法 token（logit mask））

优点：输出绝对合规
缺点：增加推理延迟（每步都要计算 FSM）
