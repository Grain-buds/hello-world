### function_call稳定性
* 存在问题
  * 模型输出的内容包括内容输出参数和schema命名不一致、内容输出参数缺少、内容输出参数类型错误、内容输出不存在的函数名、内容输出日期格式不对等
* schema 不规范
  * 函数名
  * 参数名
  * 是否必填
* prompt 上下文不严谨、系统消息有歧义、被截断、信息缺少
* 采用策略不合理：
  * 温度太高：温度越高，随机越大（0~0.2最好），走确定性
    * 通过 softmax 函数调整模型输出词的概率分布。温度越高，概率分布越平缓，高概率词和低概率词的差距缩小，模型更易选择低概率词，生成内容更具随机性；温度越低，概率分布越尖锐，高概率词的优势越明显，模型更倾向于选高概率词，输出越确定。取值范围通常为 0 - 1，部分场景也会用到大于 1 的值。
    * Temperature=0 时 Top-P 失效 → 源于采样机制的底层逻辑 
      * Temperature 的核心是缩放 logits（模型输出的原始分数）：
        * 公式：scaled_logits = logits / Temperature
        * 当 Temperature=0 时，scaled_logits 中最高概率词的分数会趋近于无穷大，其他词的分数相对可忽略，最终 softmax 后最高概率词的概率≈100%，模型会强制选择该词（即 “贪心搜索”）。
        * Top-P 的核心是 “在候选词集合中采样”，但当 Temperature=0 时，候选词集合仅剩 1 个（最高概率词），此时 “累积概率达到 P” 的筛选逻辑失去意义 —— 无论 P 设为 0.1 还是 0.9，最终只能选这一个词，因此 Top-P 失效。
  * top-p太随机， 0.8   
    * 又称累积概率采样，与固定筛选数量的 Top - K 不同，它会动态筛选候选词。具体是从高概率词开始累加，当累计概率达到阈值 P 时停止，只在这个候选词集合中采样。取值范围为 0 - 1，P 值越高，纳入的候选词越多，生成内容越多样；反之则候选词范围窄，输出越聚焦。
  * 有两个实用搭配技巧：一是当 Temperature 设为 0 时，Top - P 的作用会失效，因为模型已固定选最高概率词；二是常规场景中，建议二者搭配使用而非单独调优，比如 “Temperature = 0.5 + Top - P = 0.8” 可满足多数对话类需求，“Temperature = 0.8 + Top - P = 0.95” 适合创意类场景。
